3사전학습 가중치 vs 랜덤 초기화

from_pretrained(..., output_loading_info=True)의 missing_keys 실측. BLIP는 텍스트 인코더에 cross-attention을 새로 달기 때문에 어느 백본을 쓰든 그 부분은 랜덤에서 출발한다 — 하지만 MiniLM은 LM head까지 랜덤이라는 추가 손실이 있다.

로드 경로랜덤 초기화 텐서파라미터버려지는 체크포인트 키

왜 MiniLM엔 MLM/NSP 헤드가 없나 MiniLM은 티처의 마지막 층 self-attention 분포 KL + value-relation KL만으로 학습됐다 (MLM 없음, NSP 없음). 그래서 배포 체크포인트(199 텐서 / 33,360,000 파라미터)에 cls.* 키가 아예 없다. 변환 당시 로그의 45,260,348 = 33,360,000 + 11,899,578(untied MLM head) + 770(NSP head)로 자릿수까지 분해된다 — 원래는 있었고 배포판에서 제거된 것.

토크나이저 동일성 — 바이트 단위 증명 vocab.txt의 git blob sha1이 두 repo에서 동일하다: fb140275c155a9c7c5a3b3e0e77a9e839594a938 (231,508 B). git blob sha1은 blob <size>\0<content>의 SHA-1이므로 동일 sha1 + 동일 size ⇒ 내용 완전 동일. 덕분에 [DEC]=30522, [ENC]=30523, len(tokenizer)=30524가 티처·학생에서 정확히 일치하고, LM logit 증류의 assert torch.equal(teacher_lm_input_ids, decoder_input_ids)가 구조적으로 항상 참이다.

5itm_head 기하 — 손실이 구속하지 않는 성분

itm_head는 Linear(d, 2)이고 softmax CE는 shift-invariant이므로, 손실이 구속하는 것은 차분 성분 wd = w1 − w0뿐이다(명목 770개 중 유효 385개). 합 성분 ws = w1 + w0는 손실이 방치하고 weight decay(0.05)만 천천히 깎는다. 평가는 z1(= (wd+ws)·h / 2 + …)로 랭킹하므로, ‖ws‖/‖wd‖ 가 0에 가까울수록 z1 랭킹 = gap 랭킹이 된다.

separation 원값은 스케일 비불변 — 올바른 지표는 within-query d′

separation = mean(match_gap) − mean(distractor_gap) = wd·(hmatch − hdistractor) 이므로 ‖wd‖에 정비례한다. 티처의 ‖wd‖는 학생의 2.7배(3.338 vs 1.233)라서 원값 비교는 헤드 스케일에 오염돼 있다. 스케일을 완전히 제거하려면 분모가 gap과 같은 단위여야 한다 — d′ = (평균 gap정답 − 평균 gapdistractor) / std(gapdistractor), 쿼리 내부 기준.
